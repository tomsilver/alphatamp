Currently, we've been using the kinder (kindergarden) and kinder-baselines libraries from Princeton Robot Planning and Learning (PRPL). However the kinematic2d environments have revealed great limitations for pursuing the test-time adaptive reordering problem described in @SPECTRE_METHOD_SPEC.md. Specifically, the static historical baseline, which memorizes past skeletons seen during training and their associated historical success rates (# of successes / # of appearances in training) has shown to be extremely effective for the kinematic2d environments in kinder (e.g. Obstruction2d, clutteredStorage2d, etc). While we haven't run experiments on all of the kinematic2d environments, based on examining the environment initial state distributions, available predicates, operators, etc it's a very safe guess that the historical success rate baseline, which is basically a simple lookup table that enables memorization, will be extremely effective. This is very problematic from a research perspective because there is no research gap, and no actual value-add to be gained from pursuing a learned approach.

We need to come up with a new environment with the following properties:
- sufficient skeleton diversity: currently the skeletons seen in the test set and the train set have a high amount of overlap; this easily enables memorization.
- multiple solutions to any given problem; currently, the main differences between successful skeletons are the object IDs that are used; for example, for clutteredstorage2d with 5 blocks, and 2 blocks initially blocking the shelf, a good solution that almost always works is to remove 1 block from the shelf, then place the 4 blocks off the shelf back onto the shelf. 
- multiple similar solutions to any given problem; if skeleton A works, then there should be structurally similar other skeletons that frequently get generated as alternative candidates B, C, D, etc that behave similarly to A.
- multiple dissimilar ("anti-correlated") solutions to any given problem. Suppose skeleton A and structually similar candidates B, C, D, etc work for problem 1, and structurally similar candidates skeletons X, Y, Z, etc work for problem 2. If problem 1 (and similar problems) appear 80% of the time and problem 2 (and similar problems) appear 20% of the time, then a historical success rate baseline would go through A, B, C, D then X, Y, Z; this would waste a significant amount of time, because it wouldn't understand error propagation. This is the simplest case, with only 2 problem types, and 2 skeleton types, and in general it would be ideal to have more "types" if possible. In other words, we need to create a problem in which a historical success rate baseline would have significant failure modes, whereas a more intelligent learned approach would adapt online.
- a realistic problem: we want to demonstrate that there is actually value in a test-time reordering algorithm, and if we create a problem that is too synthetic and disconnected from realistic robotic planning, then we are weakening the significance of our problem.
- compatability with bilevel planning. Ideally, we would still be able to use the RelationalHeuristicSearchAbstractPlanGenerator, BacktrackingRefiner, or the SesamePlanner provided in PRPL's bilevel-planning library. However, this may realistically be too time consuming, and adds too much additional complexity. Alternatively and more realistically, we could create toy interfaces that act similarly to the "high level" and "low level" planners without necessarily creating from scratch new samplers, etc and synthesize the abstract plans and refinement times. It's not important to create an environment as sophisticated as the ones in kinematic2d.
